# 華碩風智慧注音（Rime / 小狼毫）

在小狼毫 0.17.4（librime 1.13.1）上重現並強化華碩智慧輸入法的體驗。
所有設定都在 `rime/`。小狼毫的使用者目錄（登錄檔 `HKCU\Software\Rime\Weasel\RimeUserDir`）直接指向這個資料夾。

## 選字清單是直的
按 ↓ 展開的選字清單改成一個字一列的直排（`rime/weasel.custom.yaml` 的 `style/horizontal: false`），按鍵也跟著改：↑/↓ 移動反白，←/→ 換頁（以前是 ←/→ 移動、↑/↓ 換頁）。

- 小狼毫的排列方向是整個方案一起設定的，沒辦法「只有展開時才直排」。所以平常只有一個候選的小框看起來跟以前一樣，但**同時列出好幾個候選的地方也會變成直的**：打英文時的猜字（打的字＋最多 3 個猜字，變成最多 4 列）、送出後「接下來可能要打的詞」（最多 3 列，本來就是用 ↑↓ 切換）、符號小鍵盤（一頁 9 個）。
- 做不到的：清單上方的「候選字」標題（小狼毫沒有標題列）；反白那一列的數字不會顯示（小框靠這個把唯一候選的「1」藏起來，兩者用同一組顏色）。
- 改回橫排：把 `style/horizontal` 改回 `true` 再重新部署；按鍵仍然是 ↑/↓ 移動、←/→ 換頁。

### 選完一個字，接著選下一個
以前在清單裡按 Enter 是「選反白的字，然後把整句送出」，所以從第一個字開始改的時候，選完第一個字整句就送出去了，後面的字沒機會改。現在跟華碩一樣：

| 清單開著時 | 效果 |
|---|---|
| ↑ / ↓ | 移動反白 |
| 1–9、空白鍵、Enter | 選這個字（詞）。後面還有字的話，清單**自動移到下一個字**，列出它的候選 |
| → / ← | 不選，把清單移到後／前一個字（單一個詞的清單沒有前後可移，這兩個鍵是換頁） |
| 第一列 | 永遠是「從這裡到句尾都維持現在這樣」，在它上面按 Enter 就結束選字、關掉清單 |
| Esc | 關掉清單，已經選的保留 |
| PageUp / PageDown | 換頁 |

- 清單關掉之後，Enter 才是送出整句。所以只改一個字的時候會比以前多按一個鍵（選完要再按一次 Enter 或 Esc 關清單）；一句裡要改好幾個字時比較省，因為不用每次重新移游標、按 ↓。
- 只打一個詞（例如 `時間`）按 ↓ 選字：選的字剛好把輸入用完就直接送出，跟以前一樣；只選了前半（選「時」），清單會接著列「間」。
- 打完整句按 ↓ 選了最後一個詞之後，以前再按 ↓ 沒有反應（要先按 ←），現在會再開一次清單。

## 英文模式
連按兩下 Shift 進入英文模式後，打的字會先組起來（行內有底線），小框顯示「打的字＋最多 3 個猜字」，跟手機鍵盤一樣：

| 按鍵 | 效果 |
|---|---|
| 空白 | 送出，再打一個空格。**拼錯的字會自動修正**（recieve → receive），修正後的字先留在行內（有底線）；緊接著按 **Backspace 或 Esc 就還原**成你打的，按其他鍵就照修正的送出。送出後小框顯示**接下來可能要打的詞**（灰色），Tab 送出第一個 |
| Tab | 送出 ⇥ 的猜字：補完（pyth → python）、拼字更正（recieve → receive）、縮寫（dont → don't）、用過的 email（tim → tim.lin@…）；沒有猜字時 Tab 照常送給程式 |
| ↓ | 展開猜字，1–9 選字，空白鍵選反白的字（再加空格），Enter 選反白的字送出 |
| Backspace | 刪掉最後一個字母 |
| Enter、方向鍵、Ctrl 快捷鍵 | 先把打的字**照打的**送出（不修正），按鍵再照常送給程式（Enter 一次就能送出聊天訊息） |
| `, ; : ! ? ) "` | 拼錯的字一樣會修正（teh, → the,），其他情況照打的送出 |

- 終端機（Windows Terminal、cmd、PowerShell、Git Bash）維持「直接輸出」：按鍵直接送進程式，沒有小框。
  其他想要直接輸出的程式（例如遊戲）：在 `rime/weasel.custom.yaml` 照樣加一行 `app_options/程式.exe: { asus_en_direct: true }`（小寫檔名），重新部署。
- 全部改回直接輸出：`rime/asus_zhuyin.custom.yaml` 的 `patch:` 加上 `asus_english/compose: false`。
- 英文模式**只記 email 地址**，其他打的字都不記（見「隱私」）。寫作小幫手開著時，游標前的英文會暫時留在記憶體裡給續寫用（見下面「停頓後續寫」），一樣不存檔。

### 空白鍵自動修正（階段 14）
只在「很有把握是打錯」的時候才改，其他時候照打的送出，猜字照樣列在小框裡（Tab 可以選）。

- **會修正的**：兩個字母順序顛倒（teh、thier、wierd）、少打或多打一個重複的字母（occured、untill）、少一個字母（goverment）、後面音節的母音拼錯（definately、seperate）；沒有撇號的縮寫（dont → don't、im → I'm）、單獨的 i → I。字首大寫照樣修正並保留大寫（Becuase → Because）。
- **不會動的**：
  - 詞庫裡有的字，就算可能是別的字打錯（form／from、quite／quiet）。
  - 程式名稱、地名、聊天用語、新詞：numpy、config、github、uint、taipei、gonna。判斷的方法是修正的字要夠常用、打錯的方式要夠常見，而且沒有第二個差不多可能的字；四、五個字母的字條件更嚴（uint 不會變 unit、cron 不會變 corn）。
  - 一個字後面多一個字母（systemd、repos、configs）；第一個字母通常不會是打錯的那一個，所以差在第一個字母的幾乎不改（dtype 不是 type）。
  - 有其他大寫的字（GPU、iPhone）、有數字或符號的字（x86、node.js、e-mail）、email。
  - 三個字母的字只修正固定的幾個（teh、hte、adn、yuo、nto…），所以 aws 不會變 was。
- **還原**：修正後緊接著按 Backspace（或 Esc），行內變回你打的字，再按空白就照打的送出。**還原過的字之後不再修正**，直到小狼毫重新啟動（重開機、重新部署）；要永久保留就把它加進 `lexicon/english_words.txt`，或在中文模式打這個字後按 Ctrl+Enter。
- **按 Enter 送出不會修正**：Enter 永遠是「照我打的」。
- **程式編輯器**（VS Code、Cursor、Visual Studio、PyCharm、IntelliJ、Sublime Text）預設不修正、也不顯示下一個詞（變數名稱不是錯字），猜字照常。清單在 `rime/weasel.custom.yaml` 的 `asus_en_noauto`，刪掉那一行就會修正，照樣加一行就能關掉別的程式。
- **全部關掉**：`rime/asus_zhuyin.custom.yaml` 的 `patch:` 加上 `asus_english/autocorrect: false`。
- 中文模式裡打的英文字也會修正，做法不太一樣，見下面「中文模式裡的英文」。
- 評估（`tests/eval/autofix*.txt`，英文模式打一個字再按空白；階段 14 之前全部是 0%，因為空白鍵不修正）：

| | 拼錯的字修正了 | 拼錯的字被改成別的字 | 正確的字被改掉 |
|---|---:|---:|---:|
| 開發集（47 個錯字、79 個要保留的字） | 100% | 0% | 0% |
| 第二個開發集（96 個錯字、294 個要保留的字） | 69.8% | 0% | 0% |
| 保留測試集（51 個錯字、84 個要保留的字） | 78.4% | 2.0%（1 個） | 0% |

  沒修正的多半是比較少用的字（cemetary、definate、persistant），或是有兩個差不多可能的答案（neice 是 nice 還是 niece、politican 是 political 還是 politician）；這些照打的送出，小框裡仍然有猜字。規則是照兩個開發集調的：第一版在保留測試集有 1 個正確的字被改掉，我沒有看是哪一個，而是另外寫了第二個開發集（多了 294 個要保留的字）把規則收緊，之後保留測試集才是 0。

### 中文模式裡的英文（階段 17）
同一套判斷規則，用在中文模式打的英文字上：

- **句子中間的英文字**（後面已經接著打了別的字）：直接顯示修正後的字。例如 `這個enviroment有問題` 行內顯示「這個environment有問題」，Enter 送出的就是修正後的。
  - 想要原本打的：← 把游標移到那個字，↓，清單是「現在的字、修正的字（標「更正」）、**你打的字**、其他猜字」，選你打的那個。**選過一次之後，這個字就不再修正**，直到小狼毫重新啟動；要永久保留，就把它加進 `lexicon/english_words.txt`，或單獨打這個字按 Ctrl+Enter 送出一次。
- **正在打的最後一個字不會動**（可能還沒打完）：行內照打的顯示，小框照常列出猜字，Tab 選。這時按 **Enter 是照打的送出**。
- **英文字後面按空白**（例如在中文模式連續打英文句子）：跟英文模式一樣，先顯示修正後的字（有底線、小框顯示 `⌫你打的字`），下一個鍵才送出；緊接著按 Backspace 或 Esc 還原，還原過的字不再修正。
- 單獨一個 `i` 在句子中間不會變成 `I`（變數名稱）。程式編輯器（`asus_en_noauto`）和 `asus_english/autocorrect: false` 一樣會關掉這裡的修正。
- 評估（`tests/eval/mixed_fix*.txt`：中文句子裡夾一個拼錯的英文字，以及夾著不該改的字；整句完全正確才算對）：

| | 階段 16 | 階段 17 |
|---|---:|---:|
| 開發集（18 句有錯字、12 句不該改） | 33.3% | 90.0% |
| 保留測試集（20 句有錯字、12 句不該改） | 28.1% | 68.8% |

  開發集剩下的 3 句錯在別的地方（那個／哪個、函式／韓式，以及 `config` 被顯示成 `CONFIG`：詞庫裡有些一般的字只有全大寫的寫法。這一項後來修掉了，見「詞庫」的「英文字的大小寫」，開發集變成 93.3%，保留測試集不變）。原本的中英混打評估（`mixed`、`mixed_test`）92.5%／97.5% 不變。
- 中文模式打一個英文字再按空白（`autofix_zh`，跟英文模式同一批字）：錯字修正了 0% → 78.7%（保留測試集 70.6%）。比英文模式低，是因為有些拼錯的字在中文模式會先被當成注音（taht、jsut），那是修正之前就有的情況。

### 句子裡的短英文字
三、四個字母的英文字（app、doc、how、run、job、full）夾在中文裡用小寫打，以前常被當成注音：`把doc改一下` 變成「把剋改一下」。

- **原因**：每個字母鍵也是注音鍵，`do` 是 ㄎㄟ。斷詞把 `doc` + `改` 讀成「沒打聲調的 ㄎㄟ」加上「多按了一個鍵的 改」，這兩個手滑合起來的成本（2.7）比任何英文字都低；連 how、run 這種最常見的字也輸。這是階段 10 讓打錯鍵變得容易更正之後的副作用。
- **作法**：一個沒打聲調的音節後面**緊接著又一個手滑**（又一個沒聲調的音節、打錯鍵的音節，或句尾沒打完的鍵），第二個要多算成本（`asus_lang.lua` 的 `C_AGAIN`，2.0）。連續兩個手滑本來就少見，剛好拼成英文字的更少。
  - **只有一個手滑的不受影響**：第一聲忘了按空白，按鍵剛好是英文字的開頭（有機會 `ru`+`cjo4` 開頭是 ruc、黑色 `co`+`nk4` 開頭是 con），仍然是中文。
  - **整句都不打聲調**的打法不適用這條規則，跟以前一樣。
  - 連續兩個手滑但拼不成英文字的，照樣當成打錯鍵來更正。
- 順便修掉：句子**一開頭**的英文字（`cpu太熱了`）就算斷詞判斷成英文，顯示的還是前一個鍵留下的注音。
- 評估（`tests/eval/en_short*.txt`，整句完全正確才算對）：

| | 之前 | 現在 |
|---|---:|---:|
| 開發集（28 句夾短英文字＋5 句只漏一個聲調、不該變英文的） | 33.3% | 97.0% |
| 保留測試集（42 句，寫的時候沒有試過這些字） | 92.9% | 95.2% |
| 最常用的 400 個三字母單字，各放進 4 個句子 | 87.8% | 98.2% |
| 最常用的 400 個四字母單字，各放進 4 個句子 | 97.3% | 99.4% |

  開發集是從已知會錯的字挑的，所以原本很低；保留測試集是隨手寫的常用字，原本就大多是對的。開發集剩下的 1 句錯在中文（一次／依次）。（原本還有一句「這台電腦的 CPU」一直是錯的，後來發現是產生按鍵的工具把「台」打成 ㄧˊ，換成「這部電腦」就對了。）其他 122 項評估分數完全相同（包括打錯鍵的六組、數字、完全不打聲調），另外 `mixed_fix` 保留測試集 68.8% → 71.9%、`en_case` 保留測試集的縮寫 95.5% → 100%、有前一個字的英文猜字前三個內 83.3%／93.3% → 86.7%／96.7%。
- **代價**：如果你**有一半以上的字不打聲調**（但不是全部不打），句子裡會開始冒出英文字：拿一般句子隨機拿掉聲調來試，拿掉 30% 完全沒影響，拿掉 50% 有 3% 的句子出現英文，拿掉 80% 有 6%（以前都是 0%）。有這種習慣的話，在 `rime/asus_zhuyin.custom.yaml` 的 `patch:` 加上 `asus_lang/costs/again: 0` 關掉（1.5 是折衷：2%／2%，但開發集會多錯 3 句，比較少見的短字又變回注音）。
- **還沒解決**：
  - 單獨打一個短英文字就送出（前面沒有任何中文）：`app` 按 Enter 仍然是注音，因為還看不出你是不是打聲調的人。句子裡的沒有這個問題。
  - 打到一半時的顯示：忘了按第一聲的空白時（有機會的 `ru` 後面接 `c`），會先閃一下英文，下一個鍵就變回中文。

### 英文字的結尾在哪裡
英文字後面那個鍵，同時也是下一個字的第一個注音鍵，所以常常有兩種切法都說得通：

| 你打的 | 以前變成 | 原因 |
|---|---|---|
| `叫tim改一下` | 叫time矮一下 | `tim`＋`e` 是 time，改（`e93`）剩下的 `93` 是 ㄞˇ |
| `他說your有問題` | 他說you酒問題 | `r`＋有（`u.3`）是 ㄐㄧㄡˇ |
| `這些files有問題` | 這些file鈕問題 | `s`＋有 是 ㄋㄧㄡˇ；複數後面接「有、一、要、也」都會這樣 |

兩種切法在斷詞看來成本一樣，只差英文字的常用程度，所以永遠是比較常用的那個字贏（time 贏 tim、you 贏 your、單數贏複數）。

- **作法**：兩種切法都是「完整的英文字＋完整的音節」時，把英文字後面最多 3 個字的中文照兩種讀法各轉一次，交給語言模型比（改一下／矮一下、有問題／酒問題）。另一種切法的分數要高出 2.0（`asus_lang/edge_margin`），而且它的英文字比較少見時還要再多一點（`asus_lang/edge_rank`），才換過去。
- **打字途中會變**：後面的字還沒打完時資訊不夠，可能先顯示「叫time矮」，打到「一下」才變回「叫tim改一下」。
- **判斷錯的時候**：在英文字後面按**空白**，英文字就在那裡結束（先送出），不管後面接什麼。這兩種切法是不同的分段，沒辦法像數字那樣把另一種讀法放在第二個候選。
- **關掉**：`rime/asus_zhuyin.custom.yaml` 的 `patch:` 加上 `asus_lang/edge: false`。
- 評估（`tests/eval/en_edge*.txt`，三組：該用短的字、該用長的字、原本就對的不該被改壞）：

| | 之前 | 現在 |
|---|---:|---:|
| 開發集（25 句）整句正確 | 48.0% | 100% |
| 保留測試集（26 句）整句正確 | 30.8% | 73.1% |
| 保留測試集：英文字切對的句數 | 12 | 24 |
| 最常用的 400 個三字母單字，各放進 4 個句子 | 98.2% | 99.4% |
| 最常用的 400 個四字母單字，各放進 4 個句子 | 99.4% | 99.8% |

  保留測試集還錯的 7 句裡，5 句是英文字對了、中文轉錯（之前就有 4 句這樣），2 句英文字仍然切錯；只統計了數量，沒有看是哪幾句。五、六個字母的常用單字各 400 個，放進同樣 4 個句子全部正確。其他 132 項評估分數完全相同，`en_case` 保留測試集的一般字 90.6% → 96.9%；每鍵延遲沒有變慢。
- **還沒解決**：英文字後面的中文本身被讀成別的音（`他說air有問題` 變成「沒就有問題」：`ai` 當成沒打聲調的 ㄇㄛ，`r`＋有 當成 就），三字母單字普查剩下的 9 個錯都是這一種；以及兩種切法語言模型都覺得通順的句子。

### 下一個詞（階段 14）
英文字用空白送出後，小框用灰色列出最常接在後面的三個詞（資料是階段 13 的詞對表 `asus_en_follow`）：

- **Tab** 送出第一個詞和一個空格，接著再預測下一個；按其他任何鍵預測就消失，按鍵照常作用。接著打字時，猜字也會優先猜常接在前一個字後面的詞（thank + y → you）。
- 句號之後不預測。方案選單裡的「預測開／預測關」開關（中文的預測也是它）、`asus_english/predict: false` 都可以關掉。
- 評估（`tests/eval/english_next*.txt`，各 30 組，例如 thank → you、according → to；之前沒有這個功能）：開發集第一個就對 76.7%、前三個內 86.7%；保留測試集 80%／86.7%。
- 只看前一個字，所以 the、of 這類字後面的預測很籠統；看整句的續寫要等之後的本機模型。

### 停頓後續寫（階段 16）
寫作小幫手（`start_assist.bat`，見下一節）開著的時候，英文模式多一件事：**打完一個字按空白後停一下（約 0.6 秒），小框的第一個提示會換成一整段**，是本機模型看你這一句前面打的內容寫的。例如打完 `I look forward to hearing from ` 停一下，出現 `you`；`Thank you very ` 出現 `much for your help.`。

- **Tab** 送出整段和一個空格，接著再預測；按其他任何鍵就消失、照常打字。繼續打字不停頓的話什麼都不會出現。
- 最多 6 個字，到句尾為止。原本的單字預測（下一個詞）排在它後面。
- **小幫手沒開就沒有這個功能**，其他一切照舊（只剩單字預測）。模型第一次用要載入約 4 秒，所以開始打字後的第一次停頓通常來不及。
- 評估（`tests/eval/continue*.txt`：一句話的開頭，第一個接的字幾乎是固定的，例如 `Sorry for the late` → reply／response）：

| 第一個字就對 | 只看前一個字的詞對表（階段 14） | 本機模型看整句 |
|---|---:|---:|
| 開發集（34 句） | 17.6% | 94.1% |
| 保留測試集（35 句） | 31.4% | 80.0% |

  模型每次約 0.2 秒，加上 0.6 秒的停頓，大約停下來 1 秒內出現。

- **怎麼做到的**：輸入法的 Lua 沒有計時器、不能連網，只在按鍵時執行。所以：
  1. 英文模式把「游標前面、經由輸入法打出來的英文」記在記憶體裡（最多 600 個字元）。按方向鍵、Enter、Tab、任何 Ctrl／Alt 快捷鍵，或切到中文模式，就清掉（游標可能移走了）；超過兩分鐘沒打字也清掉。
  2. 每次「字＋空白」之後，把這段文字寫進一條**具名管道**（`\\.\pipe\asus_zhuyin_assist_in`）交給小幫手；你接著打字就通知取消。
  3. 小幫手等 0.6 秒沒有新的請求才問模型，答案準備好後**替你按一下 F24**。輸入法收到 F24 就從另一條管道讀回答案、顯示在小框裡；F24 永遠被輸入法吃掉，不會送進你的程式。只有發出請求的那個視窗還在最前面時才會按。
- **隱私**：這段文字只在記憶體和本機管道裡，不寫進任何檔案，管道拒絕遠端連線，模型只聽 `127.0.0.1`。但要知道：開著小幫手時，你在英文模式打的英文會交給本機的模型程式。終端機（直接輸出）和程式編輯器（`asus_en_noauto`）不會送。密碼欄位通常會自己關掉輸入法；不放心的話可以關掉這個功能。
- **關掉**：`rime/asus_zhuyin.custom.yaml` 的 `patch:` 加上 `asus_english/continue: false`（輸入法不送），或 `assist/config.json` 加上 `"continue_in_ime": false`（小幫手不接）。停頓長度：`"pause_ms": 600`。
- 限制：滑鼠點到別的位置輸入法不會知道，那之後的第一次續寫可能接錯地方（按任何鍵就消失）；只看得到經由輸入法打的字，貼上的、原本就在文件裡的看不到；只有英文模式。

### 英文模式打久了不再變慢
階段 14 順便修掉的問題：猜字用的暫存資料在英文模式從來不會清掉，打過的字越多、每個按鍵越慢（評估時連續打 650 個字，每鍵從 2.4 ms 漲到 14 ms；小狼毫不重開的話會一直累積）。現在每鍵固定約 2 ms。

## 寫作小幫手（階段 15）
輸入法只看得到「正在打的那個字」，整句的文法、改寫要另一個程式來做。`assist/` 是一個常駐的小程式，在任何程式裡都能用：

1. 執行 `start_assist.bat`（畫面上會閃一下「寫作小幫手已啟動」）。
2. 在任何地方**選取一段英文**，按 **Ctrl+Alt+W**。沒有選取時，會自動選「這一行從開頭到游標」。
3. 滑鼠旁邊出現小視窗，裡面是修正後的文字，**改過的地方有黃色底**，下面列出 Harper 找到的問題。
4. **Enter** 把視窗裡的文字貼回去取代原本選取的；**Esc** 什麼都不改。

| 按鍵／按鈕 | 效果 |
|---|---|
| Enter | 套用視窗裡的文字（點進文字框自己再改幾個字也可以，這時用 Ctrl+Enter 套用） |
| Esc | 取消，原文不動 |
| 1 修正 | 只改文法、拼字、標點，盡量不動你的用字（預設） |
| 2 自然／3 精簡／4 正式／5 親切 | 整段改寫成那種語氣 |
| 6 續寫 | 在後面接一句 |
| 結束小幫手 | 關掉程式，把顯示卡記憶體還回去 |

- **全部在本機**：文法規則用 [Harper](https://github.com/Automattic/harper)（Apache 2.0），修正和改寫用 [llama.cpp](https://github.com/ggml-org/llama.cpp) 跑的 Qwen3.5-4B（4-bit，Apache 2.0）。模型只聽 `127.0.0.1`，沒有任何文字離開這台電腦，也不記錄你檢查過的內容。
- **速度**（RTX 3070 Laptop）：第一次按要載入模型約 4 秒，之後一句話約 0.25 秒、一封五句的 email 約 1.2 秒。模型佔約 3 GB 顯示卡記憶體，10 分鐘沒用就自動卸載（下次再用又要等 4 秒）。
- **中英夾雜**：「修正」會保留中文、只改英文（我明天會 recieve 那個 package → receive）；「改寫」是給整段英文用的，夾中文時會被一起改成英文。
- **剪貼簿**：取字和貼回是用 Ctrl+C／Ctrl+V 做的。剪貼簿原本的**文字**會還原；如果原本放的是圖片或檔案，會被蓋掉。
- **終端機不能用**（Ctrl+C 在那裡是中斷程式），小幫手會直接提示、不送按鍵。
- 設定（選用）：建立 `assist/config.json`，例如 `{"hotkey": "ctrl+alt+w", "idle_minutes": 10, "line_if_empty": true}`。快捷鍵被別的程式佔用時啟動會提示（這台電腦上 Ctrl+Alt+G 已經被別的程式註冊了，所以預設用 W）。
- 想要開機自動啟動：把 `start_assist.bat` 的捷徑放進「啟動」資料夾（Win+R 輸入 `shell:startup`）。預設沒有幫你設。
- 第一次使用（或換電腦）：`python tools/fetch_assist.py` 下載約 3.4 GB 到 `third_party/` 和 `models/`，每個檔案都會核對發行者公布的 SHA-256。只要文法規則、不要模型：`python tools/fetch_assist.py harper`（12 MB），這時只有「修正」能用，而且只改 Harper 有規則的錯。

評估（`tests/eval/grammar*.txt`：40 句各有一個華語使用者常犯的文法錯誤＋20 句正確的句子；「修好」是指結果跟我事先列的正確寫法完全一樣）：

| 保留測試集 | 修好 | 改成別的寫法 | 沒改到 | 正確的句子被改 | 每句秒數 |
|---|---:|---:|---:|---:|---:|
| 只用 Harper（規則） | 25% | 10% | 65% | 0% | 0.76 |
| 只用模型 | 85% | 12.5% | 2.5% | 5%（1 句） | 0.23 |
| Harper 先改、模型再改 | 87.5% | 10% | 2.5% | 5%（1 句） | 1.01 |

- 開發集：Harper 30%／模型 87.5%／兩者 85%，正確的句子都沒有被改。模型「改成別的寫法」的 5 句裡 4 句其實也對（due to the manager being sick、said to me that…），1 句沒改完（He doesn't know nothing）。
- 所以小幫手顯示的修正用**模型**的結果，Harper 只負責在下面**說明**它找到的問題（它快、不會亂改，但像 look forward to hear、He go to school 這類錯它沒有規則）。沒下載模型時才退回用 Harper 的建議。
- 模型有 5% 的機會動到本來就對的句子，所以**不會自動套用**：一定是你看過黃色的地方、按 Enter 才貼回去。

## 打錯鍵自動更正
打字時手滑的五種情況都會試著更正（小框顯示「更正」，原本打的結果在 ↓ 第二個）：

| 手滑 | 例子 |
|---|---|
| 按到旁邊的鍵 | ㄈ 打成 ㄌ：吃飯 → 喫爛 |
| 多按一個鍵 | ㄉㄨㄛ 中間多一個 ㄊ |
| 少按一個鍵 | 今 ㄐㄧㄣ 少了 ㄣ：我今天 → 我機天 |
| 兩個鍵順序顛倒 | 聲調按太早（ㄇㄧˋㄢ → 面）、下一個字的第一個鍵搶在聲調前（你好 ㄋㄧㄏˇㄠˇ） |
| 聲調不對 | ㄗㄚˋ（沒有這個音）→ 在 |

- 拼不成音節的：把上面每一種「還原」後拼得成的音節都列出來，用語言模型挑前後兩個字最通順的。
- 拼得成音節、但整句明顯不通的（換鍵、少按）：每個字前後各看兩個字，語言模型分數要高出很多（`asus_typo/margin`、`asus_typo/ins_margin`，預設 30）才更正；如果更正後語言模型把幾個單字合成一個詞（我｜機｜天 → 我｜今天），18 分就夠（`asus_typo/merge_margin`）。句尾右邊沒有上下文，門檻是 `asus_typo/end_margin`（18）。
- 第一聲的字打錯一個鍵會長得像英文（說 ㄕㄨㄛ 打成 gui）：按空白時，如果當成「打錯一鍵的注音」比當成英文字合理，空白就算第一聲，不會送出英文。
- **數字不會被當成打錯**：整串都是數字鍵（13、16）、數字後面接完整的字（3點、10日）、完整的字後面接數字（是8月），都當數字。
- 你親手選過的字（名字、術語）附近不更正。
- 評估（每句一個手滑，開發集／保留測試集，都是 100 句）：

| | 換成旁邊的鍵 | 同左，在句尾 | 多按一鍵 | 少按一鍵 | 順序顛倒 | 一般句子 |
|---|---:|---:|---:|---:|---:|---:|
| 階段 7 | 53% ／ 56% | 59% ／ 49% | 57% ／ 50% | 24% ／ 28% | 3% ／ 7% | 96% ／ 90% |
| 階段 10 | 74% ／ 75% | 69% ／ 60% | 84% ／ 79% | 56% ／ 59% | 78% ／ 77% | 96% ／ 90%（不變） |
| 階段 12 | 75% ／ 76% | 72% ／ 60% | 84% ／ 79% | 56% ／ 59% | 78% ／ 77% | 96% ／ 90%（不變） |

- 代價：每個按鍵平均多 1 ms（3.6 → 4.6 ms，最慢的 1% 從 7 ms 變 10 ms）。
- `tools/latency.py` 在階段 11 改成每句打完按 Enter 送出再打下一句（跟實際使用一樣，更正用的快取每次送出都會清空），並單獨量 Enter：穩定後每鍵平均 5.2 ms、最慢 1% 約 12 ms；Enter 平均 8 ms，句尾是數字鍵要重新判斷時約 17 ms（最慢 25 ms）。（階段 11 那次量到「剛啟動第一輪特別慢」，之後重跑三次都沒有再出現，是那一次的雜訊。）
- 每鍵延遲會隨**還沒送出的字數**變長，因為 librime 每按一鍵都把整串重新轉換：10 個字約 4 ms、30 個字約 12 ms、50 個字約 20 ms（原廠注音方案同樣是線性增加，只是基數小：0.5 → 5 ms）。一口氣打超過 50 個字不送出才會開始有感覺。
- 試過但沒採用：少按一鍵的門檻降到 20 可以多救 8 句，但保留測試集有一句正確的句子被改錯，所以維持 30。
- 還是沒改到時，用 ← 把游標移過去，↓ 選字。
- 關閉：`rime/asus_zhuyin.custom.yaml` 的 `patch:` 加上 `asus_typo/enabled: false`。

## 句中改字
一長串打完才發現中間有錯字時：← 移到錯的字前面（或 Home 到開頭再 →），↓，選字，Enter 送出。
- 游標前面的字會被「鎖住」（選成固定的字），後面的字照原樣顯示，所以只有你選的那一段會變。
- 改字評估（`tests/eval/edit*.txt`，打完整句後把轉錯的地方改對）：

| | 舊方法（↓ 從句首一段一段選） | 游標 |
|---|---:|---:|
| 開發集：改得好 | 72.7% | 100% |
| 開發集：平均按鍵 | 5.9 | 4.6 |
| 保留測試集：改得好 | 83.3% | 100% |
| 保留測試集：平均按鍵 | 5.7 | 4.3 |

舊方法改不好的多半是句子裡有數字或英文的情況（↓ 只能選最後一段）。用游標選的字也會被自我學習記住。

清單改成「選完自動跳下一個字」之後（見「選完一個字，接著選下一個」），同一份評估全部都還改得好，平均按鍵是：開發集游標 4.7 → 5.5、先按 ↓ 6.4 → 7.1；保留測試集游標 4.3 → 4.5、先按 ↓ 5.7 → 5.8。多出來的是「選完要多按一個鍵關清單」，這些句子大多只有一個錯字；一句有兩個以上的錯字時會少按。

打完直接按 ↓ 現在列的是最後一個詞：錯在最後一個詞（剛打完就發現）時只要 2 個鍵（游標要 4 個）；錯在前面時先 ↓ 再 Esc 改用游標，會多按 2 個鍵（開發集平均 6.4 鍵、保留測試集 5.7 鍵，全部改得好）。

## 數字
大千式鍵盤的每個數字鍵也是注音（1 ㄅ、2 ㄉ、5 ㄓ、8 ㄚ、9 ㄞ、0 ㄢ，3 4 6 7 是聲調），所以只在「當注音不合理」時才判斷成數字：
- 數字評估集（`tests/eval/numbers*.txt`，上排數字鍵直接打）：開發集 0% → 97.5%，保留測試集 0% → 82.5%。
- 打中文時中途不會閃出數字（`dev_partial`：0%），一般句子、中英混打、的得地、個人詞彙的分數都沒有變。
- 代價：在完整的字後面多按到一個數字鍵，以前會被當成贅字略過，現在會變成數字（多打一鍵的測試從 23%／25% 降到 21%／18%）。
- 打字途中句尾的數字鍵會先顯示成還沒打完的注音（`10` → 辦，因為你可能正要打 ㄅㄢˋ）；**按 Enter 或 Ctrl+標點送出時**會重新判斷，句尾的數字鍵就是數字（買1送1、我排第2、他是9）。只有「聲調按太早」而且語言模型也這麼認為時才當成注音（見面 ㄇㄧˋㄢ）。
- **數字後面第一個字**（階段 11 改過）：數字會把輸入切成幾段，後面那一段轉換時看不到前面的字，所以量詞常選錯（3科蘋果）。現在的做法：
  - 第一個音節在量詞表（`asus_lang.lua` 的 `MEASURE`，約 100 個）裡時，把「前面兩個字＋數字的讀法＋這一段」一起再轉一次（住三晚、考三科、第二章寫完了、第二張照片），取那個位置的字；這個字必須是該讀音常接在數字後面的詞之一（`MEASURE_ALSO`：張／章、級／集、顆／科、碗／晚、部／步…），否則用原本的字或量詞表的預設字。
  - 只改這一個字；原本的轉換結果排在 ↓ 第二個。
  - **你在數字後面選過的字會記住**：例如「第3」後面選過「集」，下次「第＋數字＋ㄐㄧˊ」就先出「集」（記的是「數字前一個字＋讀音」）。
  - 之前的做法是硬換（第N＋ㄓㄤ 一律「章」、第N＋ㄐㄧˊ 一律「集」），會把「第2張照片」「第2級警戒」改錯，而且排在個人學習之後。
  - 還是分不出來的：單獨的「第3集／第3級」「第3張／第3章」（語言模型兩個都接受），選一次就會記住。
  - 代價：硬換的規則在測試句上剛好是對的，拿掉之後數字的保留測試集少一句（80% → 77.5%）、第二個開發集少一句（88% → 86%，「這是第1集」變成「第1級」）；換來的是我另外列的 37 個「數字＋量詞」短句從對 19 個變成對 25 個，而且不再有改不回來的字。
- 第二個開發集 `tests/eval/numbers_more.txt`（50 句：句尾的數字、後面不是量詞的單一數字、小數、長數字）：74% → 88%；原本的開發集 97.5%、保留測試集 80% 不變。
- **數字鍵也是注音的聲母時**（階段 12）：1、2、5 就是 ㄅ、ㄉ、ㄓ，所以「5＋ㄨㄢˋ」是 5萬 也是「賺」、「2＋ㄨㄟˋ」是 2位 也是「對」、「12萬」是「1段」。以前一律當注音，5萬、2位、12萬、2碗飯全部打不出來。現在兩種讀法都交給語言模型比（前後各看兩個字，數字當成它的讀法：只要賺就好／只要五萬就好），數字的讀法分數夠高才採用：
  - 只在數字後面是量詞表裡的詞（萬、位、碗、億…）時，或前面已經有數字（1＋段 → 12＋萬）時才考慮。
  - 採用時小框標「數字」，原本的中文讀法在 ↓ 第二個；緊接在另一個數字前面不採用（賺25萬）；一開頭就打的要更高的分數。
  - 評估（`tests/eval/numbers_amb*.txt`，各 30 句）：開發集 0% → 76.7%、保留測試集 3.3% → 73.3%；一般句子、打字途中不閃數字（0%）、個人詞彙都不變。
  - 還分不出來的（語言模型兩種都覺得通順）：請問5位嗎、只要5萬就好、再2位、這個要12萬。這時數字的讀法排在候選**第二個**：把游標移到那個字（或按 Home）再按 ↓ 就看得到，標著「數字」。
  - **選過會記住**：不管是把中文改成數字，還是把自動選的數字改回中文，下次同樣的「前一個字的讀音＋這個讀音」就照你選的（記在 `asus_learn.userdb`）。
  - 數字鍵盤（numpad）永遠輸出數字，不受這些判斷影響。
- 還做不到的：`10大` 的按鍵和 `10284` 一樣，只能按 ↓ 選；數字後面那個詞沒有前文可參考（他是8月「升」的）。

- **英文字的大小寫**：中文模式用小寫打的英文字，如果詞庫裡的寫法在第一個字母以外還有大寫，就換成那個寫法（api → API、nato → NATO）。但 `easy_en` 有三千多個字只有全大寫的寫法，其中很多是一般的字和人名（CORE、FAX、ADMIN、ALICE、CONFIG、BRANSON），所以以前打 core 會變成 CORE。現在 `build_lang_data.py` 只在「看起來是縮寫」時才保留全大寫：
  - 最多 5 個字母，而且 SymSpell 的詞表（全小寫的一般單字）沒有這個字，才保留大寫：USA、NATO、HTML、RISC、CPU。其他的照你打的小寫：core、aids、alice、adams、americas、config。
  - 規則判斷錯的用兩份小清單修正（`build_lang_data.py` 的 `ACRONYMS`：unix、bios、rom、atm、unesco、eeprom 等 36 個仍然大寫；`PLAIN`：bool、func、addr、mkdir 等 23 個照打的）。
  - McCartney、MHz 這種大小寫混合的寫法不動；用 Shift 打的大寫永遠照打的。
  - `lexicon/english_words.txt` 裡的字照你寫的，優先於以上全部：想要某個字固定大寫或固定小寫，把你要的寫法加進去再重新產生詞表。
  - 一共 514 個字改成小寫。詞頻和「這串按鍵算不算英文」的判斷都沒有變；猜字、拼字更正、下一個詞用的也是同一個寫法（alic 補完成 alice，不再是 ALICE）。

| | 一般的字、人名照打的小寫 | 縮寫變成大寫 |

  - 其他評估集：中英混打（`mixed`、`mixed_test`）92.5%／97.5% 不變；`mixed_fix` 開發集 90.0% → 93.3%（`config`）；有前一個字的英文猜字（`english_ctx`）第一個就猜對 70%／70% → 73.3%／83.3%，因為以前打到 int、reg 這種「本身就是全大寫條目」的開頭時，第一個候選是 INT、REG；其餘 118 項分數完全相同。

  - **看前一個英文字**：`rime/opencc/asus_en_follow.*` 記每個英文字後面最常接的 40 個字（SymSpell 的詞對資料）。打完 `machine` 再打 `lea`，第一個猜的是 learning；打完 `new` 再打 `yor` 會被認成英文並猜 York。前一個字是中文或標點時不套用。

  詞表放在 OpenCC 字典裡（`rime/opencc/asus_en.*`），不放在 Lua 記憶體，否則每次按鍵會慢約 40 ms。

## 自我學習
小狼毫本身就會記住你打過的句子；`asus_learn.lua` 再加上三件事，學到的資料都存在 `rime/asus_learn.userdb`（只在本機）。

- **改字**：展開候選改掉某個詞再送出，就記成「這組注音：原本的詞 → 你選的詞」，連同前後的字。
  - 前後的字一樣時，立刻改用你選的詞。
  - 其他句子：只改過一次而且從來沒改回去，就直接套用；如果兩個方向都改過（例如「程式」和「城市」），就只看前後文。
  - **你自己常打的詞不會被換掉**：被換掉的詞如果你最近自己打過（例如平常就會打「城市」），學到「程式」後只在相同前後文套用；小狼毫自己的學習把它換掉時也會換回來。
  - 被學習換過的地方，小框會標「學」，↓ 第二個就是原本的。
  - 單一個字，以及只差在「在／再／的／得／地」的詞，一定要前後的字都相同才會套用。
  - 被學到的詞換掉時，原本的轉換結果會排在候選第二個，按一次就能改回來；改回來也會被記住。
  - 想要「改兩次才套用到所有句子」（比較不會誤改別的句子，但學得比較慢）：在 `rime/asus_zhuyin.custom.yaml` 的 `patch:` 加上 `asus_learn/global_after: 2`。
- **英文詞**：用 Ctrl+Enter 送出的字母、句子裡打過的英文詞。
- **下一個詞**：把你送出的文字切成詞，同樣的兩個詞前後出現兩次（或接受預測一次），之後就會排在預測的第一個。
- **淡化**：學到的東西每 90 天權重減半（`asus_learn/half_life_days`），太舊的會自動刪掉。
- **忘記**：Shift+Del（見上表）。整個清空：結束小狼毫服務 → 刪除 `rime/asus_learn.userdb` 資料夾 → 重新啟動。
- **關閉**：`rime/asus_zhuyin.custom.yaml` 的 `patch:` 加上 `asus_learn/enabled: false`，再重新部署（小狼毫自己的學習不受影響）。

## 部署
1. 修改 `rime/` 裡的檔案。
2. 系統匣的小狼毫圖示按右鍵 →「**重新部署**」。
3. 如果是改了 `RimeUserDir`，或是第一次在新電腦上使用：先跑 `python tools/fetch_models.py`、`python tools/build_lexicon.py` 和 `python tools/build_lang_data.py`，再重新啟動小狼毫服務（重開機最簡單），然後重新部署。
4. 詞表的快速格式（選用，但建議）：`build_lang_data.py` 若找到 `third_party/opencc-build/src/tools/Release/opencc_dict.exe`，會把 `rime/opencc/` 的詞表轉成二進位的 ocd2，小狼毫啟動後第一次打字的載入時間從約 1.8 秒降到約 0.5 秒。編譯方法（需要 Visual Studio 2022 Build Tools）：下載 [OpenCC 1.1.9](https://github.com/BYVoid/OpenCC/archive/refs/tags/ver.1.1.9.tar.gz) 解壓到 `third_party/`，用 VS 內附的 cmake 執行 `cmake -S third_party/OpenCC-ver.1.1.9 -B third_party/opencc-build -G "Visual Studio 17 2022" -A x64 -DBUILD_DOCUMENTATION=OFF -DENABLE_GTEST=OFF -DPYTHON_EXECUTABLE=<python.exe>`，再 `cmake --build third_party/opencc-build --config Release --target opencc_dict`。沒有這個工具時照常用文字詞表。

### 不會卡死的兩道保險
- **輸入法本身**：`asus_lang.lua` 的斷詞如果在同一個按鍵內重來超過 100 次，或 1 秒內對同一串輸入重來超過 300 次（正常打字最多幾次），那一串就改用原廠斷詞，並在日誌記一筆。按鍵內的計數是為了抓「每秒不到 300 次」的慢速迴圈。最壞的結果是那一串選字比較差，下一個鍵照常運作，不會整個凍住。
- **測試工具**：任何一個按鍵超過 30 秒沒回應（環境變數 `RIME_KEY_TIMEOUT` 可調），測試程序就自己結束（結束碼 124），只印出按鍵的形狀（字母→a、數字→0），不會印出保留測試集的內容。日誌只記警告以上。評估跑完如果保險被觸發過，會印出 `rime_harness: the segmentation guard tripped`，代表有 bug 要修。

## 學習資料備份
學到的東西（`rime/*.userdb`、`emails.txt`、`shortcuts.txt`、`*.custom.yaml`、`lexicon/*_words.txt`）每天自動備份一份到 `backups/learn/<日期-時間>/`，只在本機、不進 git。

- **排程**：Windows 工作排程器的 `RimeLearnBackup`（只屬於你的帳號）。每 2 小時檢查一次，當天還沒備份、而且鍵盤滑鼠已經 2 分鐘沒動，才會備份；當天已有備份就什麼都不做。
- **為什麼要等閒置**：小狼毫執行時會把資料庫最新的部分鎖住，別的程式讀不到，所以備份時要把小狼毫服務停掉約 1–3 秒再啟動，那幾秒打不出中文。
- **會驗證**：每份備份都會實際打開讀一次、數裡面有幾筆（改字、下一個詞、英文詞、email…），結果寫在 `backup.json`；打不開的備份標成 BAD，不會被拿來還原。筆數比上一份少一半以上時不刪任何舊備份。
- **保留**：最近 14 個有備份的日子各留最新一份，再加最近 12 個月每月最新一份。
- 指令（都在專案資料夾執行）：

```
C:\Users\User\anaconda3\python.exe tools\backup_learn.py              現在備份一次（會停 1–3 秒）
C:\Users\User\anaconda3\python.exe tools\backup_learn.py --list       列出備份
C:\Users\User\anaconda3\python.exe tools\backup_learn.py --restore latest         看看會還原什麼（不會動）
C:\Users\User\anaconda3\python.exe tools\backup_learn.py --restore latest --yes   真的還原；現有資料先移到 backups\learn\_before-restore-…
C:\Users\User\anaconda3\python.exe tools\backup_learn.py --uninstall  取消每日排程（--install 重新註冊）
```
- 排程每次執行的結果記在 `backups/learn/backup.log`。
- **還原是全有或全無**：先核對備份的每個檔案和備份當時的雜湊值一致，在現有檔案旁邊準備好完整的一份並再核對一次，才停掉小狼毫、把現有資料移到一旁、換上新的；任何一步失敗就把已經做的步驟全部倒回去。

## 切換視窗時保留沒送出的字
原版小狼毫在切換視窗時會把還沒送出的字刪掉。`patches/weasel/` 是對小狼毫本身（C++ 的 `WeaselTSF`）的修補，讓行內已經顯示的字留在文件裡。
- 這是唯一不在 `rime/` 裡的改動：換的是 `C:\Windows\System32\weasel.dll` 和 `C:\Windows\SysWOW64\weasel.dll`（原檔備份在旁邊），重新部署不會影響它，小狼毫更新後要重裝。
- 實機測試：`python tools\tsf_test.py` 會開記事本自動打字、切視窗、讀回文字（約 1 分鐘，期間不要碰鍵盤滑鼠）。目前 6 項全過；Word、瀏覽器、VS Code 要手動試。
- 安裝、還原、重新編譯的方法，以及第一版為什麼沒生效，寫在 `patches/weasel/README.md`。

## 隱私
- 學習資料（`*.userdb`，包括 `asus_learn.userdb` 記下的「詞→下一個詞」）、建置檔、同步目錄、個人詞彙匯出檔都列在 `.gitignore`，而且只存在本機。
- 停頓後續寫：小幫手開著時，英文模式打的英文會經由本機的具名管道交給本機模型（只在記憶體，不存檔、不連網）；見「停頓後續寫」。
- 英文模式還原過的自動修正只記在記憶體裡（小狼毫重新啟動就忘記），不寫進磁碟。
- 英文詞的學習只從中文模式送出的文字學。英文模式雖然會組字，但只記長得像 email 地址的字（name@host.com），其他打的字一律不記，所以就算某個程式的密碼欄位沒有關掉輸入法，密碼也不會被存下來（除非它長得像 email）。終端機是直接輸出，完全不經過組字。
- 記住的 email 存在 `rime/asus_learn.userdb`（只在本機），`rime/emails.txt` 不進 git。
- 寫作小幫手（`assist/`）的模型和文法檢查都在本機執行，只在你按快捷鍵時讀取選取的文字，不存檔、不連網。
- 沒有設定任何雲端同步目錄。舊設定裡的 Google Drive 同步路徑沒有沿用。
